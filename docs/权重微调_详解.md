# 权重微调（Fine-tuning）详解：每一步在做什么

> 目标读者：第一次接触「模型微调」的新手。
> 本文用「放试管」这个具体任务，把「什么是微调」「为什么用 LoRA」「数据从哪来」「训练命令每行在做什么」「产物是什么」从头到尾讲清楚。

---

## 一、先建立一个直觉：什么叫"微调"

想象一个**什么都会一点、但什么都不是最专业的**通用人才——这就是 π0.5 的**基座模型（base model）**。它见过海量的互联网图片、文字和机器人数据，所以：

- 它看得懂图像（知道什么是试管、什么是架子）；
- 它听得懂语言（知道「放进去」是什么意思）；
- 它懂得机器人怎么动（知道手臂该怎么协调）。

但它**不知道"你这台臂 + 你的桌面 + 你的试管架"这个具体场景**该怎么操作。你的机械臂型号、你的相机角度、你桌面上的橙色试管架，这些细节它从没见过。

**微调（fine-tuning）就是：拿你自己的几十条示范数据，让这个通用模型"补课"，把它变成一个「专门在你的场景里放试管」的专家。**

结论一句话：**基座模型 = 通才；微调后的模型 = 专才。**

---

## 二、为什么用 LoRA，而不是"全量微调"？

### 2.1 全量微调的问题

π0.5 的基座模型有几亿到几十亿参数（PaliGemma 2B + gemma_300m）。如果"全量微调"（full fine-tuning），意味着：

- 每一个参数都要算梯度、更新；
- 显存里要同时放：模型权重 + 梯度 + 优化器状态，通常是推理时的 3~4 倍；
- 每存一个 checkpoint 都是几个 GB。

这对家用/单卡服务器（比如你的 DGX Spark）来说压力很大，而且没必要——你只是想让它学会"放试管"，不需要重写它已经会的一切。

### 2.2 LoRA 的思路：只训练一小撮"增量"

LoRA（Low-Rank Adaptation，低秩适配）的核心洞察是：

> 微调造成的权重变化，其实可以用一个**低秩矩阵**来近似。

具体做法：对模型的某些关键层（比如注意力层的 `q`、`v` 投影，以及状态/动作的输入输出投影），**冻结原始权重不动**，在旁边**并联一个小的可训练矩阵**：

```
输出 = 原始权重 · 输入  +  (B · A) · 输入
        ↑ 冻结不动            ↑ 只训练这个（很小）
```

`A` 和 `B` 是两个小矩阵，它们的乘积 `B·A` 的"秩"（rank）很低，所以叫"低秩"。这个 `B·A` 就是**适配器（adapter）**。

好处：

1. **可训练参数极少**：可能只占原模型的 0.1%~1%，训练快、显存省。
2. **产物极小**：一个 adapter 可能就几十 MB，而不是几个 GB。
3. **基座不动**：你可以在同一个基座上训练多个任务的 adapter，随时切换。

### 2.3 LoRA 的两个关键参数

| 参数 | 含义 | 对效果的影响 |
|---|---|---|
| `r`（rank，秩） | 低秩矩阵的"宽度"，决定 adapter 的表达能力 | r 越大越接近全量微调，参数也越多；太小可能学不动 |
| `lora_alpha` | 缩放系数，实际缩放 = `lora_alpha / r` | 控制 adapter 对输出的影响强度 |

leRobot 里默认还会**自动选目标层**：对 π0.5 这类模型，通常微调「动作专家」的 `q_proj`/`v_proj` 层 + 状态投影 + 动作投影矩阵（这些最可能跟具体任务相关），而冻结视觉编码器和语言骨干的大部分。

> 这正是你之前服务器目录名里带 `lora` 的原因：`pi05_tubes_lora_...` = 「π0.5 + 放试管 + 用了 LoRA」。

## 三、微调的数据从哪来、长什么样

### 3.1 数据 = 遥操作示范

模型要学的"正确动作"，来自于**人遥操作示范**：你手动掰从臂（leader），主臂（follower）跟着动，把「放试管」这个动作标准地做一遍，同时录下：

- 每一帧的**状态**（7 个关节角）；
- 每一帧的**动作**（示范中的关节角，作为"正确答案"）；
- 每一帧的**两张图**（俯瞰 front + 腕部 wrist）；
- 一句话**语言指令**（`place two test tubes into the orange rack`）。

录很多遍（episode），就是一个"示范数据集"。**模型要学的就是：给定"当前状态 + 图像 + 指令"，预测出"下一步动作"，让它尽量接近你示范的动作。**

### 3.2 数据集的物理结构

```
my_b601/place_tubes_<时间戳>/      ← 一个数据集 = 一个 repo_id
├── videos/
│   ├── observation.images.front/   ← 俯瞰相机视频
│   └── observation.images.wrist/   ← 腕部相机视频
├── data/
│   └── ...parquet                  ← 每帧的状态+动作数值（表格）
└── meta/
    ├── stats.json                  ← 归一化统计（训练必读）
    └── info.json                   ← 元信息（关节名、指令、fps 等）
```

### 3.3 为什么 `stats.json` 这么关键

模型训练前，要把"度数"（比如 -30°、120°）归一化到一个小范围（比如 [-1,1]），否则数值量级差异会干扰训练。π0.5 用的是**分位数归一化**，所以它读的是 `stats.json` 里的 `q01` 和 `q99`（第 1% 和第 99% 分位数），而不是简单的 min/max。

**这就是为什么推理时 `predict_server.py` 里也有一行 `STATS_PATH`**——训练和推理必须用同一套统计，否则数值对不上，模型输出就乱了。

> ⚠️ 风险点：录制工具生成的 `q01/q99` 是一个"保守包络"，数据量少（比如只有 10 条）时，这个统计可能不够准。可以训练后用 `augment_dataset_quantile_stats.py` 重新扫描真实分位数。

## 四、微调命令：每一行在做什么

用「放试管」为例，训练命令长这样（服务器上执行）：

```bash
conda activate lerobot
lerobot-train \
    --dataset.repo_id=my_b601/place_tubes \
    --policy.type=pi05 \
    --policy.pretrained_path=/root/pi05_b601/models/pi05_base \
    --peft.method_type=LORA \
    --peft.r=32 \
    --peft.lora_alpha=32 \
    --policy.dtype=bfloat16 \
    --policy.device=cuda \
    --policy.gradient_checkpointing=true \
    --batch_size=8 \
    --steps=3000 \
    --save_freq=500 \
    --output_dir=outputs/pi05_tubes_lora \
    --job_name=pi05_tubes_lora \
    --seed=1000
```

逐行解释：

| 行 | 在做什么 |
|---|---|
| `lerobot-train` | 训练入口命令 |
| `--dataset.repo_id=my_b601/place_tubes` | **用什么数据**：你刚录的 10 条示范数据 |
| `--policy.type=pi05` | **用哪个模型**：π0.5 |
| `--policy.pretrained_path=.../pi05_base` | **从哪起步**：加载基座模型权重（不是从零开始，是"补课"） |
| `--peft.method_type=LORA` | **怎么训**：用 LoRA，只训适配器，冻结基座 |
| `--peft.r=32` | LoRA 的秩（低秩宽度） |
| `--peft.lora_alpha=32` | LoRA 缩放系数 |
| `--policy.dtype=bfloat16` | 用 bf16 半精度，省显存提速 |
| `--policy.device=cuda` | 在 GPU 上训练 |
| `--policy.gradient_checkpointing=true` | 用显存换算力：不存中间激活，省显存（代价是稍慢） |
| `--batch_size=8` | **每次梯度更新看几条数据**：8 条。显存不够就调小 |
| `--steps=3000` | **总共训练多少步**（一个 step = 处理一个 batch） |
| `--save_freq=500` | 每 500 步存一个 checkpoint |
| `--output_dir` / `--job_name` | 结果存哪、叫什么名字 |
| `--seed=1000` | 随机种子，保证结果可复现 |

### 几个新手最容易混淆的概念

**1. step vs epoch vs batch_size**

- `batch_size`：一次喂给模型几条数据（比如 8 帧）。
- `step`：模型处理完一个 batch、更新一次权重 = 1 步。
- `epoch`：把整个数据集从头到尾过一遍。

你有 10 条 episode、假设共 3000 帧数据、batch_size=8，那么一个 epoch ≈ 375 步。`--steps=3000` ≈ 8 个 epoch。**你直接关心的只有 `--steps`：步数越多，学得越"熟"，但也越可能"背答案"（过拟合）。**

**2. 为什么数据少，步数不能太多**

10 条数据非常少。如果步数太多，模型会把这几条数据"背下来"，换个位置就废（过拟合）。所以少数据 → 少步数 + 早点停。你之前 `fast_1000`、`fast_4000` 里的数字就是步数。

**3. 训练会自己挑"动作维度"**

π0.5 内部把动作补到 32 维，但你的任务只有 7 个关节。训练时会**只用前 7 维算损失**，后 25 维忽略——这个你不用管，是自动的。

## 五、训练产物长什么样、怎么用

训练过程中，每 `save_freq` 步会在 `output_dir/job_name/` 下存一个 checkpoint：

```
outputs/pi05_tubes_lora/
└── checkpoints/
    ├── 000500/
    │   └── pretrained_model/     ← 这就是一个可用的 LoRA adapter
    ├── 001000/
    │   └── pretrained_model/
    ├── 001500/
    │   └── pretrained_model/
    └── ...
```

**每个 `checkpoints/NNNN/pretrained_model` 就是一个完整可加载的 adapter**，数字越大 = 训练越久。

于是推理时 `predict_server.py` 里这两行就对应起来了：

```python
BASE_DIR    = '/root/pi05_b601/models/pi05_base'          # 基座（冻结）
ADAPTER_DIR = '.../checkpoints/005000/pretrained_model'   # 你训练的 adapter
```

加载时 `PeftModel.from_pretrained(base, adapter)` 把两者合体。**「换权重」= 把 `ADAPTER_DIR` 指向不同数字的 checkpoint 目录**，仅此而已。

## 六、你之前的训练发生了什么

你的服务器上有这些目录，从命名就能反推：

| 目录名 | 解读 |
|---|---|
| `pi05_tubes_lora_first100_fast_1000` | π0.5 + 放试管 + LoRA + 用前 100 条数据 + 快训 + 1000 步 |
| `pi05_tubes_lora_100_200_fast_4000` | π0.5 + 放试管 + LoRA + 用 100~200 条数据 + 快训 + 4000 步 |

它们的 `checkpoints/` 下就是你之前拿来推理的 `001000`、`005000` 等 adapter。

**为什么真机成功率低？** 直接原因就是：数据少（100~200 条）+ 步数少（1000~4000 步）+ 任务难（放试管是精细操作）。所以你现在要**自己录数据、重新微调**——这就是整个项目的闭环。

## 八、微调的常见坑与风险

| # | 坑 | 说明 | 应对 |
|---|---|---|---|
| 1 | **数据太少 → 过拟合** | 10 条数据背死答案，换位就废 | 少步数、早停、多录几条 |
| 2 | **stats.json 不一致** | 训练和推理必须用同一套 q01/q99 | 别改 STATS_PATH；重新扫描分位数用 `augment_dataset_quantile_stats.py` |
| 3 | **显存不足（OOM）** | batch_size 太大 | 调小 batch_size、开 gradient_checkpointing、用 bf16 |
| 4 | **语言指令不一致** | 训练时的 `single_task` 和推理时的 `TASK` 必须一字不差 | 固定死这句话，复制粘贴 |
| 5 | **步数太少学不动 / 太多过拟合** | 少数据尤其敏感 | 用 save_freq 存多个 checkpoint，逐个试 |
| 6 | **方向约定** | 自录数据的 `joint_directions` 若和之前数据集不同，STATE_FLIP 要重验 | 微调后真机干跑复验方向 |

## 九、一句话总结

- **微调** = 拿你自己的示范数据，让通用 π0.5 变成"放试管专家"。
- **LoRA** = 只训练一小撮低秩增量矩阵（adapter），冻结基座，省显存、产物小、可切换。
- **数据** = 遥操作录的（状态 + 动作 + 双相机图 + 一句话指令），归一化靠 `stats.json` 的 q01/q99。
- **训练** = 一条 `lerobot-train` 命令，核心是 `--dataset`（数据）、`--policy.pretrained_path`（起步基座）、`--peft.method_type=LORA`（怎么训）、`--steps`（训多久）。
- **产物** = `outputs/<job_name>/checkpoints/NNNN/pretrained_model`，换权重 = 换这个路径。
