# 真机连接（Real Machine Connection）详解：每一步在做什么

> 目标读者：第一次接真机机械臂的新手。
> 本文把「电脑 ↔ 机械臂 ↔ 相机 ↔ 服务器」这一整套连接，拆成四条独立链路，逐条讲清楚「物理上连的是什么、软件上怎么建立、怎么验证、内部发生了什么」。

---

## 一、连接总览：一共四条链路

你整套系统里有**四条互相独立的连接**，出问题时必须分清是哪一条，不要混在一起排查：

| 链路 | 物理连接 | 软件接口 | 作用 |
|---|---|---|---|
| ① 主臂 follower | 达妙电机 ←→ PCAN-USB 转接头 ←→ 电脑 USB | SocketCAN `can0` @ 1 Mbps | 发指令让主臂动、读主臂关节角 |
| ② 从臂 leader | FashionStar 总线舵机 ←→ USB 串口线 ←→ 电脑 | 串口 `/dev/ttyUSB0` @ 1 Mbps | 你手掰从臂，电脑读它的角度作为示范 |
| ③ 相机 ×2 | USB HD Camera ←→ 电脑 USB | `/dev/video6`(front)、`/dev/video4`(wrist) | 拍图给模型看 |
| ④ 服务器 | 电脑 ←→ 网络 ←→ GPU 服务器 | SSH 隧道 `localhost:8080` | 把图+状态发给服务器，拿回动作 |

**记忆口诀：CAN 管主臂，串口管从臂，video 管相机，隧道管服务器。** 四条互不干扰。

---

## 二、链路①：主臂 follower 的 CAN 连接

### 2.1 物理上连的是什么

主臂（reBot B601-DM）里的 7 个达妙电机，用的是 **CAN 总线**通信。CAN 是工业里一种"多设备挂一根线、靠报文 ID 区分"的总线协议。你的电脑没有原生 CAN 口，所以用一个 **PCAN-USB 转接头**把 CAN 转成 USB 插到电脑上。

### 2.2 软件上怎么建立（SocketCAN）

Linux 把 CAN 转接头抽象成一个网络接口 `can0`（就像网卡 `eth0` 一样）。建立连接的步骤：

```bash
# 1. 先关掉（若已存在）
sudo ip link set can0 down

# 2. 设成 CAN 接口，波特率 1 Mbps（关键：必须和电机一致）
sudo ip link set can0 type can bitrate 1000000

# 3. 打开
sudo ip link set can0 up
```

### 2.3 怎么验证连上了

```bash
ip -details -statistics link show can0
```

看两个关键点：

- `state UP`：接口起来了；
- `ERROR-ACTIVE`：总线无错误，正在正常收发。

再看统计里的 `tx`/`rx`（发送/接收包数）是否在涨。如果 `tx` 一直涨、`rx` 一直是 0，说明发出去没人应——可能没接电机或接线错。

> ⚠️ 最常见的坑：波特率。电机和 `can0` 必须都是 1 Mbps，一个对不上就全收不到。你的电机是 1 Mbps，所以固定写 `bitrate 1000000`。

## 三、链路②：从臂 leader 的串口连接

### 3.1 物理上连的是什么

从臂（reBot Arm 102）里有 7 个 **FashionStar 总线舵机**，它们用一条**串口总线**串联（daisy-chain），再通过一根 USB 串口线连到电脑。每个舵机有一个 **id（0~6）**，电脑靠 id 找对应舵机。

### 3.2 软件上怎么建立

串口线插上后，Linux 会自动生成设备文件 `/dev/ttyUSB0`（第一个 USB 串口设备）。软件通过这个文件读写字节流即可。

### 3.3 怎么验证连上了（ping）

```bash
python ~/桌面/rebot_bridge/ping_leader.py
```

脚本做的事：用 `FashionStarServo('/dev/ttyUSB0', baudrate=1000000)` 打开串口，然后对 id=0~6 逐个发 `ping`，看谁回话。**返回 `True` = 那个舵机在线**。

### 3.4 两个高频坑

1. **权限**：报 `serial error: Permission denied` → 你没有读 `/dev/ttyUSB0` 的权限。解决：`sudo usermod -aG dialout $USER` 后重新登录（一劳永逸），或临时 `sudo chmod 666 /dev/ttyUSB0`。

2. **7 个全 ping 不到（你现在遇到的）**：如果电源灯亮、串口能打开、换 4 个波特率都全 False，那**不是软件/波特率问题，是数据线（信号线）物理没通**。因为 7 个舵机是一条总线串联，上游断一个 = 全部失联。重点排查：
   - 是不是**通过拓展坞**连的（USB-串口过拓展坞经常出供电/时序问题）→ 改成直插主板 USB 口；
   - 总线插头、数据线两头是否松动；
   - `ls -l /dev/ttyUSB*` + `dmesg | grep -i tty` 确认从臂到底在 `ttyUSB0` 还是 `ttyUSB1`（拓展坞可能多生成了串口）。

## 四、链路③：相机连接

### 4.1 物理上连的是什么

两个 USB HD Camera，一个架在**俯瞰位**拍工作区（front），一个在**腕部**拍近景（wrist）。

### 4.2 软件上怎么建立

每个 USB 相机对应一个 `/dev/videoN` 设备。**编号不固定**——USB 重新插拔/重启后可能变。所以每次开机先确认：

```bash
v4l2-ctl --list-devices
```

找到两个相机的编号（你现在是 `video6`=front、`video4`=wrist）。

### 4.3 两个关键参数（你踩过的坑）

| 参数 | 为什么要设 | 你的值 |
|---|---|---|
| 分辨率 width×height | 相机在非标准分辨率下帧率会掉 | **640×480**（不是 848×480，那个只有 15fps） |
| fourcc | 指定视频编码格式，不设可能读不到帧 | **MJPG** |

这两个设对了，相机才能稳定出 30fps 的图。验证就是看 `lerobot-record` 或评估脚本能不能持续读到帧而不超时。

## 五、`connect(calibrate=True)` 内部到底做了什么

每次脚本调用 `robot.connect(calibrate=True)`，内部是按顺序做这些事（以主臂 follower 为例）：

```
1. MotorBridgeController(channel=port)    ← 建立 CAN 通信层（打开 can0）
2. _add_motors_to_bus()                    ← 把 7 个电机按 motor_can_ids 挂到总线上
3. 若没校零过且 calibrate=True → calibrate()  ← 需要则先校零（见第六节）
4. 对每个相机 cam.connect()               ← 打开相机、设分辨率/fourcc、预热
5. configure()                             ← 给电机写初始配置（PID、限位、方向等）
6. 若 calibrate=True → detect_gripper_zero()  ← 夹爪归零检测（见 6.4）
```

**关键点：**
- 第 1~2 步对应链路①（CAN）；第 4 步对应链路③（相机）。所以 `connect` 失败时，报错会告诉你卡在哪一步，据此判断是 CAN 还是相机问题。
- 第 3 步的"校零"是**条件触发**的：只有检测到"还没校零"才做。所以如果你换了台电脑或删了校准文件，第一次 `connect` 会要求校零。

## 六、校零（Calibration）是什么、为什么需要

### 6.1 电机需要一个"零位参考"

达妙电机的编码器读的是**相对角度**（从某个零点开始算）。但"哪个位置是 0°"这个参考，电机自己不知道——它需要一个"零位"基准，存在电机的 EEPROM（掉电不丢）里。

**校零（calibrate）就是：手动把臂摆到一个已知姿势（通常是伸直零位），告诉电机"你现在就是 0°"，把参考写进 EEPROM。**

### 6.2 什么时候需要校零

- 新机器第一次用；
- 电机重新上电后零点漂了（你遇到的 353.96° 就是夹爪零点漂了快一整圈）；
- 换了校准文件（比如换了电脑）。

### 6.3 校零命令

```bash
lerobot-calibrate --robot.type seeed_b601_dm_follower --robot.port can0
```

按提示：先把整臂摆到零位、夹爪闭合，然后回车。它会逐个电机写零位。

### 6.4 夹爪归零检测（detect_gripper_zero）

夹爪（dm4310）校零后，脚本会做一次自检：让夹爪轻轻闭合，读它当前角度，如果跟"零位"差超过 15°（`tolerance_deg=15`），就报：

```
gripper zero-detect: gripper not homed, offset 353.96 deg
```

意思就是"夹爪的零点参考漂了，请重新校零"。**这不是夹爪坏了，是零点丢了，重新 `lerobot-calibrate` 即可。**

### 6.5 一个重要澄清

校零**只改电机的零位参考**，**不影响**限位、方向、尺度。因为这些信息来自代码里的 `config`（`joint_limits`、`joint_directions`），`send_action` 用的是 config 而不是校准文件。所以重新校零不会把限位搞坏，放心校。

## 七、链路④：服务器连接（SSH 隧道）

### 7.1 为什么要隧道

模型推理要 GPU，在服务器上跑。本机的评估/控制脚本要调服务器的推理接口。但服务器只监听自己的 `localhost:8080`，本机够不着。

**SSH 隧道**就是把服务器的 `localhost:8080` 映射到本机的 `localhost:8080`：

```bash
ssh -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
    -L 8080:localhost:8080 -p 6022 root@43.155.204.215
```

之后本机脚本 `POST http://localhost:8080/predict`，数据会自动通过 SSH 加密隧道转发到服务器。

### 7.2 三个参数在做什么

- `-L 8080:localhost:8080`：本地 8080 → 转发到服务器的 localhost:8080。
- `-p 6022`：SSH 端口是 6022（不是默认 22）。
- `ServerAliveInterval=30` / `ServerAliveCountMax=3`：每 30 秒发心跳、连续 3 次失败就断——防止隧道挂掉后一直假连接。

### 7.3 验证

```bash
curl http://localhost:8080/health
# 返回 {"ok":true} 就说明隧道通、服务器在跑
```

## 八、端到端数据流全景（评估时）

把四条链路串起来，一次完整推理的数据流是这样的：

```
[链路③] 相机拍两张图 (front + wrist)
[链路①] 主臂读 7 个关节角（度）
        ↓ 打包成 JSON
[链路④] POST http://localhost:8080/predict（走 SSH 隧道）
        ↓ 服务器：归一化 → 拼 prompt → 模型推理 → 反归一化
        返回 50×7 动作
[链路④] 本机收到
[链路①] 把动作按 30fps 逐帧发到主臂（send_action）
        ↓ 主臂动，世界状态改变
        循环：重新读状态+拍照 → 再推理（这就是"分块闭环"）
```

**链路②（从臂 leader）只在"录数据"时用**：你手掰从臂，电脑读从臂角度，主臂跟着动，同时录下示范。

## 九、常见连接问题速查表

| 症状 | 哪条链路 | 原因 | 解决 |
|---|---|---|---|
| `can0` 不是 UP / 收发 0 | ① CAN | 波特率错 / 没接电机 / 转接头没插 | 重设 `bitrate 1000000`、重插转接头、`ip link show can0` 查状态 |
| `serial error: Permission denied` | ② 串口 | 没权限 | `usermod -aG dialout $USER` 重新登录 |
| `Servo not found (id=0)`，7 个全 False | ② 串口 | 数据线没通（拓展坞/松动） | 直插 USB、重插总线、核对 ttyUSB0/ttyUSB1 |
| `gripper not homed, offset 353.96°` | ① 主臂 | 夹爪零点漂了 | `lerobot-calibrate` 重新校零 |
| `failed to set fps=30 (actual_fps=15)` | ③ 相机 | 分辨率不支持 30fps | 改成 640×480 |
| `Timed out waiting for frame` | ③ 相机 | fourcc 探测错 | 加 `fourcc: MJPG` |
| `curl localhost:8080` 不通 | ④ 隧道 | 隧道没开/服务器没起 | 重开隧道、`tail -f server.log` 看服务器 |
| 相机图是黑的/编号错 | ③ 相机 | USB 重新枚举编号变了 | `v4l2-ctl --list-devices` 重新确认 |

## 十、一句话总结

- **四条独立链路**：CAN（主臂）、串口（从臂）、video（相机）、SSH 隧道（服务器）。
- **连接** = 物理插好 → 软件建接口（`can0`/`ttyUSB0`/`videoN`/`8080`）→ 验证（`ip link`/`ping`/`v4l2-ctl`/`curl health`）。
- **`connect(calibrate=True)`** 按固定顺序做：开 CAN → 挂电机 → 必要时校零 → 开相机 → 写配置 → 夹爪自检。
- **校零** = 给电机定零点参考，只改零点、不动限位方向；报 353.96° 就是零点丢了，重新校。
- **排查** = 先分清是哪条链路，再按上表对症下药，不要四条混着查。
