## 第一部分：项目背景与整体架构

### 1.1 目标

把微调好的 π0.5（pi05）视觉-语言-动作（VLA）模型部署到 Seeed reBot B601-DM 机械臂上，完成**真实环境下的推理与评估**；在评估不理想后，转向**自己录制遥操作数据、准备用自采数据重新微调**。

整个项目的逻辑链是：

```
遥操作录数据 → 用数据微调 π0.5 → 真机部署推理 → 评估成功率 → 不理想就再录数据再微调
```

本会话走到了「评估脚本就绪 + 准备录数据」这一步，卡在从臂（leader）的物理接线。

### 1.2 硬件清单

| 角色 | 设备 | 接口 | 说明 |
|---|---|---|---|
| 主臂（follower） | Seeed reBot B601-DM | CAN（PCAN-USB → SocketCAN `can0` @ 1 Mbps） | 6 个达妙 `dm4340p` 关节 + 1 个 `dm4310` 夹爪，共 7 轴。**这是执行动作的臂** |
| 从臂（leader） | reBot Arm 102（FashionStar 总线舵机） | USB 串口 `/dev/ttyUSB0` @ 1 Mbps | 遥操作输入，7 个总线舵机（id 0~6）一条总线串联。**这是你手掰、用来示范动作的臂** |
| 相机 | USB HD Camera ×2 | `/dev/video6`=front(俯瞰)、`/dev/video4`=wrist(腕部) | 推理和录制都要用 |

**两个臂是两套完全独立的链路，不要混淆：**

- 主臂 follower → 走 **CAN**（`can0`，PCAN-USB 转接头）。
- 从臂 leader → 走 **USB 串口**（`/dev/ttyUSB0`）。
- 判断主臂用 CAN 命令（`candump` / `ip link`），判断从臂用串口命令（`ping` / `ls /dev/ttyUSB*`）。

### 1.3 两台机器与数据流

| 称呼 | 实际 | 用途 |
|---|---|---|
| 本机 | `user@user-virtual-machine`（Ubuntu 虚拟机，带桌面） | 机械臂走 CAN、两个相机、跑控制/录制脚本、开 SSH 隧道 |
| 服务器 | `43.155.204.215:6022`（`root@gx10-a9b2`，NVIDIA DGX Spark） | GPU 跑模型推理（`predict_server.py`），**无 SSH 免密，命令要你自己用密码登录执行** |

**数据流向（评估/推理时）：**

```
本机（读 7 关节角度 + 两张相机图）
   → POST http://localhost:8080/predict（走 SSH 隧道）
   → 服务器（模型推理，返回 50×7 动作）
   → 本机（把动作按 30fps 发到主臂）
```

SSH 隧道命令（本机执行）：

```bash
ssh -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
    -L 8080:localhost:8080 -p 6022 root@43.155.204.215
```

### 1.4 关节约定（单一事实来源）

7 关节顺序（数据集 / 模型 / 驱动三者一致）：

```
shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_yaw, wrist_roll, gripper
```

本机驱动 `joint_directions`（`config_seeed_b601_dm_follower.py`）：

```python
{shoulder_pan: -1.0, shoulder_lift: -1.0, elbow_flex: 1.0,
 wrist_flex: 1.0, wrist_yaw: 1.0, wrist_roll: -1.0, gripper: -6.0}
```

`joint_limits`（度）：

```python
{shoulder_pan: (-145,145), shoulder_lift: (-170,0), elbow_flex: (-200,0),
 wrist_flex: (-80,90), wrist_yaw: (-90,90), wrist_roll: (-130,130), gripper: (-270,0)}
```

**单位**：全程用「度」。
- `get_observation()` 返回**原始编码器角度**（度，物理量，未套方向）。
- `send_action()` 收**逻辑量**（度），内部先乘 `joint_directions`，再 clip 到 `joint_limits`，再转弧度、按 `motor_can_ids` 发 CAN 帧。

**重要结论**：校零（calibration）只改电机零位参考，**不改限位/方向/尺度**——`send_action` 用的是 `config.joint_limits`，不是校准文件里的范围。所以重新校零不会把限位搞坏。

## 第二部分：模型与推理链原理（如何实现）

### 2.1 模型结构

π0.5 = **PaliGemma 2B**（视觉-语言骨架）+ **gemma_300m**（动作专家）+ **SigLIP**（视觉编码器），推理用 bf16。

- **LoRA 微调**：不训练整个大模型，只训练一小撮「低秩适配器」参数。使用时通过 `PeftModel.from_pretrained(base, adapter_dir)` 把适配器套在冻结的基座上。
- 输出：`predict_action_chunk(batch)` 返回形状 `(1, 50, 32)`——**50 是动作块长度（chunk=50 帧），32 是动作维度上限，只有前 7 维是真实关节**，后 25 维是填充。

### 2.2 四个关键配置（服务器 `predict_server.py`）

| 变量 | 值 | 含义 |
|---|---|---|
| `BASE_DIR` | `/root/pi05_b601/models/pi05_base` | **基座模型**：π0.5 原始预训练权重，冻结不变，占显存大头 |
| `ADAPTER_DIR` | `/root/pi05_b601/outputs/pi05_tubes_lora_100_200_fast_4000/checkpoints/005000/pretrained_model` | **LoRA 适配器**：微调出来的「增量」权重。**换权重就是换这一行** |
| `STATS_PATH` | `/root/pi05_b601/datasets/orange_rack_test_tubes_848/meta/stats.json` | **归一化统计**：训练数据的 q01/q99 分位数，负责「度数 ↔ [-1,1]」换算 |
| `TASK` | `place two test tubes into the orange rack` | **语言指令**：拼进 prompt 开头 |

**一句话理解：**

- `BASE_DIR` = 谁在干活（基座大脑）。
- `ADAPTER_DIR` = 学了啥（微调的增量，几 MB~几十 MB）。
- `STATS_PATH` = 数值怎么换算（度数和 -1~1 之间）。
- `TASK` = 任务是什么（一句话）。

这四者共同决定一次推理。**换权重 = 改 `ADAPTER_DIR` 这一行，其他三个不变**（前提是还是同一个「放试管」任务、同一套归一化统计）。

### 2.3 推理链六步（`predict_server.py` 的 `predict()`）

**第 1 步 · 状态翻转：**

```python
s = STATE_FLIP * state_deg   # STATE_FLIP = -1.0
```

把本机读到的 7 关节角度（度）整体取负。原因：你的机器 `joint_directions` 与训练数据正好相反（7 个关节全反），所以喂给模型前要把状态翻回来。

**第 2 步 · 分位数归一化：**

```python
s_norm = 2.0 * (s - q01) / (q99 - q01) - 1.0   # 落到 [-1,1]
```

用训练数据的分位数 q01/q99（不是 min/max，抗离群点）把任意度数线性映射到 [-1,1]。

**第 3 步 · 离散化 256 桶：**

```python
s_disc = np.digitize(s_norm, np.linspace(-1,1,257)[:-1]) - 1
s_disc = np.clip(s_disc, 0, 255)
```

π0.5 用「离散 token」表示连续数值（和语言 token 同一套词汇表），把 [-1,1] 切成 256 个桶，每个关节变成一个 0~255 的整数 token。这就是为什么「状态被塞进了语言 prompt」。

**第 4 步 · 拼 prompt：**

```python
prompt = f"Task: {cleaned}, State: {state_str};\nAction: "
```

`state_str` 是 7 个 0~255 整数用空格连起来，例如 `Task: place two test tubes into the orange rack, State: 0 128 255 64 100 3 127;\nAction: `。然后 tokenize（padding='max_length', max_length=200, truncation）。

**第 5 步 · 模型推理：**

```python
actions = policy.base_model.predict_action_chunk(batch)
```

`batch` 里含两张图（`observation.images.base_0_rgb`=front、`observation.images.left_wrist_0_rgb`=wrist）+ 语言 token + attention mask。模型一次预测 50 帧动作。

**第 6 步 · 动作反归一化：**

```python
actions_deg = (actions + 1) / 2 * (q99 - q01) + q01
actions_deg = actions_deg[:, :7]   # 只取前 7 维
```

动作从 [-1,1] 反归一化回「度」。**注意动作方向不翻转**（动作空间训练和你这边一致），只有状态翻转。

### 2.4 图像格式（关键细节）

- 模型期望图像 **∈ [0,1]**。`decode_image` 里 `arr = np.array(img)/255.0`。
- 模型内部 `_preprocess_images` 会 `img*2-1` 转成 [-1,1] 喂 SigLIP，尺寸内部 `resize_with_pad` 到 224×224。
- 图像 key 名是固定的：`observation.images.base_0_rgb`（俯瞰）+ `observation.images.left_wrist_0_rgb`（腕部）。写错了模型会报「image features missing」。

### 2.5 方向约定（本项目核心结论）

**state 全部取负喂模型；action 不翻转、直接发。**

推导依据（已交叉验证）：

1. `get_observation()` 返回原始编码器（物理量），`send_action()` 输入是逻辑量（内部套方向）。
2. 训练数据集的 `joint_directions` = 本机驱动的**负值**（这是数据集从别的臂格式转换时产生的）。
3. 夹爪 `-6.0` 是「尺度」，不是单纯符号，由本机 `send_action` 内部消化，脚本层面不用管。

> ⚠️ 方向约定是**必须真机才能 100% 确认**的项。本会话之前已通过非零位姿干跑证实方向正确，但**每次重新校零后应复验一次**（见 7.3）。

### 3.4 任务讨论（结论）

用户想换更简单的任务（"把矿泉水瓶碰一下就算成功"）。结论：

**换任务 ≠ 改 `TASK` 文字。** 模型是「放试管」这个任务的专用权重，改文字会让模型「听着新指令、但动作还是老的」，输出会乱。要做新任务，唯一正确路径是：**重新录新任务的数据 → 重新微调 → 重新部署**。

用户随后确认：**还是先做「放试管」任务，用自录数据重新微调**，因为当前权重训练时间太短（只有 1000~5000 步），真机成功率低。

### 3.5 遥操作采集准备

用户决定「先不推理，回到遥操作，录 10 条数据」用于重新微调。任务仍是「放试管」。当前卡在从臂舵机 ping 不到（见 6.5）。

### 3.6 关于「RTC / 实时」与「推理一部分执行一部分」的澄清

- 用户问「现在是 RTC 吗」：代码里没有「RTC」这个词。当前是**分块闭环控制（chunk-level closed-loop）**：模型一次预测 50 帧 → 执行完这 50 帧（约 1.65s）→ 重新读状态和图像 → 预测下一个 50 帧。不是「离线一次性算完所有动作」。
- 用户问「不是推理一部分实际执行一部分吗」：**当前不是边推理边执行的流水线**。是串行的「整块推理 → 整块执行 → 再推理」。每个 chunk 之间，臂会停顿一下等下一次推理。如果要做真正的流水线（执行第 N 块时并行推理第 N+1 块），需要改脚本，本会话没做。

## 第四部分：评估脚本实现（`eval_pi05_robot.py`）

### 4.1 设计目标

把「50 次评估」自动化为一个循环：每个 episode 之间**人工复位场景 + 机械臂**、跑一次、**人工判定成功 y/n**、最后打印成功率。

### 4.2 关键参数

| 参数 | 含义 | 默认 |
|---|---|---|
| `--episodes` | 评估 episode 数（=「50 次」的 50） | 50 |
| `--steps-per-episode` | 每个 episode 跑几个 50 帧 chunk | 1 |

一个 chunk = 一次模型预测的 50 帧动作，以 30fps 执行 ≈ 1.65s。**放试管这种 pick-place 通常要 5~15s，默认 1 个 chunk 太短，需调大**（例如 `--steps-per-episode 5` 约 8s）。

### 4.3 每个 episode 的流程

```
1. 提示「复位场景+机械臂后按回车开始（q 退出）」
2. 自动跑 steps_per_episode 个 chunk：
     读状态+相机 → POST /predict → 执行 50 帧（每帧发动作 + sleep 0.033s）
3. 提示「成功? [y/n/q]」→ 记录结果
4. 打印当前累计成功率，追加写 eval_results.log
```

最后打印：`=== 评估完成: N/50 成功 = 百分比 ===`。

### 4.4 用法

```bash
conda activate lerobot
python ~/桌面/rebot_bridge/eval_pi05_robot.py                          # 50 个 episode，每集 1 chunk
python ~/桌面/rebot_bridge/eval_pi05_robot.py --episodes 10            # 先试 10 个
python ~/桌面/rebot_bridge/eval_pi05_robot.py --steps-per-episode 5    # 每集 5 chunk(~8s)
```

### 4.5 关键实现细节

- **相机**：`FRONT_IDX=6`(848×480)、`WRIST_IDX=4`(640×480)，`open_cam` 里强制 `MJPG` fourcc + 预热读 6 帧。
- **机器人**：`SeeedB601DMFollowerConfig(port='can0', cameras={})`，`robot.connect(calibrate=True)`。
- **状态读取**：`state = [obs[f'{j}.pos'] for j in JOINTS]`。
- **执行节奏**：`robot.send_action(action)` 后 `time.sleep(0.033)`，对应约 30fps。
- **急停**：每个 episode 之间有回车闸门，全程 Ctrl+C 可急停，`finally` 里 `disconnect()` 释放。

## 第五部分：遥操作采集数据实现（具体步骤）

目标：录 10 条「放两根试管进橙色架」的遥操作数据，用于重新微调。

### 5.1 前置①：夹爪校零

录制脚本 `connect(calibrate=True)` 会做夹爪归零检测，若夹爪零点漂了会报 `gripper not homed, offset 353.96 deg` 错误，必须先校零：

```bash
conda activate lerobot
lerobot-calibrate --robot.type seeed_b601_dm_follower --robot.port can0
# 按提示：整臂摆零位 + 夹爪闭合，回车
```

### 5.2 前置②：确认相机编号

```bash
v4l2-ctl --list-devices
# 确认 front=video6、wrist=video4（USB 重新枚举后编号可能变）
```

### 5.3 前置③：确认从臂串口

```bash
ls -l /dev/ttyUSB*
# 确认从臂在 ttyUSB0（拓展坞可能多生成串口，导致从臂其实在 ttyUSB1）
```

### 5.4 录制命令（最终版）

```bash
conda activate lerobot
lerobot-record \
  --robot.type=seeed_b601_dm_follower \
  --robot.port=can0 \
  --robot.cameras="{front: {type: opencv, index_or_path: 6, width: 640, height: 480, fps: 30, fourcc: MJPG}, wrist: {type: opencv, index_or_path: 4, width: 640, height: 480, fps: 30, fourcc: MJPG}}" \
  --teleop.type=rebot_arm_102_leader \
  --teleop.port=/dev/ttyUSB0 \
  --dataset.repo_id=my_b601/place_tubes \
  --dataset.num_episodes=10 \
  --dataset.single_task="place two test tubes into the orange rack" \
  --dataset.push_to_hub=false
```

**逐条解释（为什么这么配）：**

- `--robot.type=seeed_b601_dm_follower`：本机主臂（follower）用的是自定义驱动，走 CAN。
- `--robot.port=can0`：CAN 口，**不是** `damiao/ttyACM0`。
- `--robot.cameras=...`：双相机，都强制 640×480、MJPG。**分辨率从 848×480 改成 640×480**（front 相机 848×480 只有 15fps，不满足 30fps）。**`fourcc: MJPG`**（不加会 `select()` 超时读不到帧）。
- `--teleop.type=rebot_arm_102_leader`：从臂（leader）用正确的驱动名。**注意不是**内置的 `rebot_102_leader`（那个 `joint_directions` 不对）。
- `--teleop.port=/dev/ttyUSB0`：从臂串口。
- `--dataset.repo_id=my_b601/place_tubes`：数据保存的仓库名。
- `--dataset.num_episodes=10`：录 10 段。
- `--dataset.single_task=...`：**任务文字固定死**，之后微调和推理的 `TASK` 要一字不差。
- `--dataset.push_to_hub=false`：不推 HuggingFace，只存本地。

**注意点：**
- **不要加 `--robot.id`**（保持跟校零时一致，默认 None，才能找到校准文件 `None.json`）。
- 若报 `rerun-sdk` 未装：去掉 `--display_data=true`，或 `pip install 'lerobot[viz]'`。

### 5.5 录制按键

| 键 | 作用 |
|---|---|
| `n` / → | 结束当前段并**保存**，进入下一段 |
| `r` / ← | **丢弃**当前段重录（别按） |
| `q` / Esc | 退出 |

每段按**两次 `n`**：第一次结束动作、第二次结束「回零位复位」。录满 10 段自动结束。

### 5.6 数据落盘位置

```
~/.cache/huggingface/lerobot/my_b601/place_tubes_<时间戳>/
├── videos/
│   ├── observation.images.front/
│   └── observation.images.wrist/
├── data/               # 每帧状态+动作 (parquet)
└── meta/
    ├── stats.json      # 归一化统计（训练要用）
    └── info.json
```

**录制前 checklist（一次全过，少返工）：**

1. 夹爪已校零（否则 connect 就报 353.96°）。
2. 相机编号对（video6=front、video4=wrist）。
3. 从臂 ping 通（否则 `Servo not found`）。
4. 串口权限（否则 `Permission denied`）。
5. 相机 fourcc= MJPG、分辨率 640×480（否则 fps/超时报错）。

## 第六部分：遇到的问题与解决（完整清单 + 排查过程）

### 6.1 `rerun-sdk` 未安装 ✅ 已解决

- **现象**：`--display_data=true` 报 `ImportError: 'rerun-sdk' is required but not installed`。
- **原因**：可视化窗口依赖 rerun，环境里没装。
- **解决**：去掉 `--display_data=true`（或 `pip install 'lerobot[viz]'`）。
- **提醒**：用户曾问「是不是忘了连接了」——**这不是连接问题**，是缺可视化包。

### 6.2 从臂串口权限 ✅ 已解决

- **现象**：`ServoBusError: serial error: Permission denied`（`/dev/ttyUSB0`）。
- **原因**：用户不在 `dialout` 组，无权访问串口设备。
- **解决**：
  - 临时：`sudo chmod 666 /dev/ttyUSB0`（重启后失效）。
  - 永久：`sudo usermod -aG dialout $USER`，然后**重新登录**。

### 6.3 相机帧率 ✅ 已解决

- **现象**：`OpenCVCamera(6) failed to set fps=30 (actual_fps=15.0)`。
- **原因**：front 相机在 848×480 这个非标准分辨率下最高只有 15fps。
- **解决**：front 改成 640×480（模型反正会缩到 224×224，原始分辨率高低无所谓，帧率 30 才重要）。

### 6.4 相机读帧超时 ✅ 已解决

- **现象**：`OpenCVCamera(4) read failed (status=False)` + `Timed out waiting for frame from camera OpenCVCamera(4) after 1000 ms`。
- **原因**：lerobot 默认 `fourcc=None`（自动探测）探测到了错误格式，读不到帧。
- **解决**：相机加 `fourcc: MJPG`（和桥接脚本 `open_cam` 里强制 MJPG 一致）。

### 6.5 从臂舵机 ping 不到 ❌ 未解决（当前阻塞）

**现象**：`RuntimeError: Servo not found for shoulder_pan (id=0)`，随后测试发现 7 个舵机（id 0~6）全部 ping 返回 False。

**排查过程（一步步排除）：**

1. **先确认 CAN（主臂）正常**——用户问「看看 can 连接」，`can0` 显示 `UP`、`ERROR-ACTIVE`、bitrate 1000000、pcan_usb 设备，tx/rx 无错误。**主臂 CAN 链路完全正常**（这跟从臂是两码事）。
2. **串口能打开**——无权限错误、能实例化 FashionStarServo。
3. **电源灯亮**——从臂有电。
4. **试 4 个波特率**（1000000/115200/921600/460800）全 False——排除波特率不对。
5. **关键线索**：从臂是**通过拓展坞（USB docking station）**连电脑的。

**当前结论**：**数据线（信号线）没通**，是物理接线问题。7 个舵机是一条总线串联，上游断一个 = 全失联。USB-串口设备过拓展坞经常出供电/数据时序问题。

**待办（按顺序试）：**

1. 从臂 USB **直接插主板口**（不过拓展坞），再跑 `python ~/桌面/rebot_bridge/ping_leader.py`。
2. 检查从臂本体总线插头、数据线两头是否松动。
3. `ls -l /dev/ttyUSB*` + `dmesg | grep -i tty | tail -20`：确认 ttyUSB0 是不是从臂（拓展坞可能多生成了串口，从臂其实在 ttyUSB1）。

### 6.6 夹爪零点漂移（gripper zero-detect）⚠️ 需重校零

- **现象**：`gripper zero-detect: gripper not homed, offset 353.96 deg`。
- **原因**：夹爪电机（dm4310）存的零点参考（EEPROM 零位）漂了，几乎一整圈（354°），典型是重新上电导致。
- **解决**：重新校零 `lerobot-calibrate --robot.type seeed_b601_dm_follower --robot.port can0`。
- **影响**：录制、评估都会在 `connect(calibrate=True)` 时卡在这里，必须先解决。
- **澄清**：校零只改电机零位，**不改限位/方向/尺度**（那些来自 config）。

### 6.7 早期：直接粘贴 Python 到 bash 报「找不到命令 from」

- **现象**：用户把 Python 代码直接贴进 bash，报语法错「找不到命令 from」。
- **原因**：Python 代码没有用 `python -c` 或写成脚本。
- **解决**：我把诊断逻辑写成 `ping_leader.py` 文件，直接 `python ping_leader.py` 跑。

## 第九部分：常见疑问 FAQ

**Q1：换权重就是改哪一行？**
改服务器 `predict_server.py` 的 `ADAPTER_DIR` 一行，其余 `BASE_DIR`/`STATS_PATH`/`TASK` 不变（同一任务前提下）。

**Q2：能不能换个任务（比如碰矿泉水瓶），只改 `TASK` 文字？**
不能。模型是「放试管」专用权重，改文字会导致「听新指令但动作还是老的」。换任务必须重新录数据 + 重新微调。

**Q3：为什么状态要取负，动作不用？**
因为训练数据的 `joint_directions` 是你机器驱动的负值。喂模型前把状态翻回训练约定；模型输出的动作空间已经和你的驱动一致，所以动作直接发。

**Q4：夹爪报 353.96° 是什么？**
夹爪电机 EEPROM 零点参考漂了接近一整圈，重新校零即可。校零不改限位方向。

**Q5：主臂和从臂是一回事吗？**
不是。主臂 follower 走 CAN（`can0`），从臂 leader 走 USB 串口（`/dev/ttyUSB0`），两条独立链路，各自排查。

**Q6：录的数据存哪了？**
`~/.cache/huggingface/lerobot/<repo_id>_<时间戳>/`，视频在 `videos/`，数值在 `data/`，统计在 `meta/stats.json`。

**Q7：现在是实时控制吗？**
是分块闭环：一次推理 50 帧 → 执行完 → 再推理。不是边推理边执行的流水线。
