# 机器人技能学习系统 · 总览（系统论视角 + 完整细节）

> 这份文档是所有碎片文档（连接详解、微调详解、会话记录、评估脚本）的**地图/骨架**。
> 系统论视角：把整个项目看成一个**闭环系统**，先立骨架，再把所有细节挂到正确的位置上。
> 一句话：**整体 = 边界 + 六个功能子系统 + 接口耦合 + 两个反馈回路**。

---

## 一、系统定义与总功能

**系统**：一个「机器人技能学习系统」。

**总功能**：让 reBot B601-DM 机械臂学会并稳定执行「把两根试管放进橙色架」（place two test tubes into the orange rack）。

**涌现性**（系统论第一定律）：单看一个电机、一个权重、一条命令都没意义；只有通过正确的关系耦合起来，系统才"涌现"出「会放试管」的能力。所以**先看关系，再看零件**。

---

## 二、系统边界：内部 vs 环境

系统论第二定律：系统靠**边界**与环境交换信息而存在。边界划清，才知道哪些是你可控的、哪些要当成外部输入。

| 边界 | 构成 | 角色 |
|---|---|---|
| **系统内部** | 机械臂×2、相机×2、本机（Ubuntu VM）、GPU 服务器（DGX Spark） | 可控，能改代码/接线/配置 |
| **外部环境** | 物理世界（试管、架子、桌面）+ 人（你） | 不可控输入/裁判 |

边界上流进流出的**信息**只有五种：图像、关节角、动作、语言指令、成功率。整个系统就是这五种信息在里面转。

---

## 三、六大功能子系统

之前按物理分（follower/leader/相机/服务器）是"零件视角"。**功能视角**才是系统视角。每个子系统下面给出：物理对应、接口、关键文件/命令/参数、典型故障。

### 3.1 感知子系统 —— 把世界变成信息

| 项 | 内容 |
|---|---|
| 物理 | 相机×2 + 主臂编码器 |
| 输入 | 物理世界（光、关节位置） |
| 输出 | 两张 RGB 图 + 7 个关节角（度） |
| 关键文件 | `eval_pi05_robot.py` 的 `open_cam()` / `read_frame()`；`robot.get_observation()` |

**相机细节（踩过的坑都在这）：**

| 相机 | 设备 | 分辨率 | fourcc | 作用 |
|---|---|---|---|---|
| front 俯瞰 | `/dev/video6` | 640×480 | MJPG | 看整个工作区 |
| wrist 腕部 | `/dev/video4` | 640×480 | MJPG | 看近景 |

- **为什么 640×480**：848×480 下 front 相机只有 15fps，不满足 30fps。
- **为什么 MJPG**：不设 fourcc 会 `select()` 超时读不到帧。
- **编号会漂**：USB 重新枚举后 video4/video6 可能变，每次先 `v4l2-ctl --list-devices` 核对。

**状态读取细节**：`get_observation()` 返回**原始编码器角度（度）**，7 个关节顺序固定：

```
shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_yaw, wrist_roll, gripper
```

### 3.2 决策子系统 —— 信息变成动作

| 项 | 内容 |
|---|---|
| 物理 | GPU 服务器上的 π0.5 模型（`predict_server.py`） |
| 输入 | 7 关节角 + 两张图 + 语言指令 |
| 输出 | 50×7 动作块（度） |
| 关键文件 | 服务器 `~/pi05_b601/src/rebot_lerobot/rerobot_bridge/predict_server.py` |

**模型结构**：PaliGemma 2B（视觉-语言骨架）+ gemma_300m（动作专家）+ SigLIP（视觉），bf16。

**四个关键配置（单一事实来源）：**

| 变量 | 值 | 含义 |
|---|---|---|
| `BASE_DIR` | `/root/pi05_b601/models/pi05_base` | 基座（冻结） |
| `ADAPTER_DIR` | `.../pi05_tubes_lora_100_200_fast_4000/checkpoints/005000/pretrained_model` | LoRA 适配器（换权重改这行） |
| `STATS_PATH` | `.../orange_rack_test_tubes_848/meta/stats.json` | 归一化统计 q01/q99 |
| `TASK` | `place two test tubes into the orange rack` | 语言指令 |

**推理六步（`predict()` 内部）：**

```
① 状态翻转   s = STATE_FLIP * state_deg      （STATE_FLIP = -1.0）
② 分位归一化 s_norm = 2*(s-q01)/(q99-q01) - 1   （落到 [-1,1]）
③ 离散化     np.digitize(s_norm, 256桶) - 1      （0~255 整数）
④ 拼 prompt  "Task: {task}, State: {7个数};\nAction: "
⑤ 模型推理   predict_action_chunk(batch)        （输出 (1,50,32)，前7维真实）
⑥ 反归一化   actions_deg = (a+1)/2*(q99-q01)+q01 （动作不翻转）
```

### 3.3 执行子系统 —— 动作变成物理改变

| 项 | 内容 |
|---|---|
| 物理 | 主臂 follower 的 7 个达妙电机（6×dm4340p + 1×dm4310 夹爪） |
| 输入 | 7 关节动作（度，逻辑量） |
| 输出 | 物理运动 |
| 关键方法 | `robot.send_action(action)`，内部 `×joint_directions → clip(joint_limits) → 转弧度 → 发 CAN` |

**方向约定（核心结论，必须真机复验）：**

```python
joint_directions = {pan:-1, lift:-1, elbow:1, flex:1, yaw:1, roll:-1, gripper:-6}
joint_limits(度) = {pan:(-145,145), lift:(-170,0), elbow:(-200,0),
                    flex:(-80,90), yaw:(-90,90), roll:(-130,130), gripper:(-270,0)}
```

- **state 取负喂模型；action 不翻转直接发**（因为训练数据的 `joint_directions` = 本机驱动的负值）。
- 执行节奏：每帧 `send_action` + `sleep(0.033)` ≈ 30fps。

### 3.4 示范子系统 —— 提供"正确行为"的目标参照

| 项 | 内容 |
|---|---|
| 物理 | 从臂 leader（reBot Arm 102，FashionStar 总线舵机 ×7，id 0~6） |
| 接口 | 串口 `/dev/ttyUSB0` @ 1 Mbps |
| 输入 | 你的手掰 |
| 输出 | 示范动作（主臂跟随 + 数据记录） |
| 关键文件 | `ping_leader.py`（诊断）、驱动 `lerobot_teleoperator_rebot_arm_102` |

**驱动名陷阱**：用 `rebot_arm_102_leader`（不是内置的 `rebot_102_leader`，后者 `joint_directions` 不对）。

**当前状态**：⚠️ **7 个舵机全 ping 不到**——数据线没通，是系统当前断点（见第七节）。

### 3.5 学习子系统 —— 用示范更新决策器

| 项 | 内容 |
|---|---|
| 物理 | GPU 服务器跑 `lerobot-train` |
| 输入 | 遥操作数据集（状态+动作+图+指令） |
| 输出 | LoRA adapter（`outputs/.../checkpoints/NNNN/pretrained_model`） |
| 方法 | PEFT LoRA（冻结基座，只训低秩增量） |

**训练命令（放试管自录数据版）：**

```bash
lerobot-train \
    --dataset.repo_id=my_b601/place_tubes \
    --policy.type=pi05 \
    --policy.pretrained_path=/root/pi05_b601/models/pi05_base \
    --peft.method_type=LORA \
    --peft.r=32 --peft.lora_alpha=32 \
    --policy.dtype=bfloat16 --policy.device=cuda \
    --policy.gradient_checkpointing=true \
    --batch_size=8 --steps=1500 --save_freq=250 \
    --output_dir=outputs/pi05_tubes_lora_my10 \
    --job_name=pi05_tubes_lora_my10 --seed=1000
```

**关键概念**：
- `batch_size`=一次喂几条；`step`=更新一次权重；`epoch`=过完一遍数据集。
- LoRA 的 `r`（秩）/`lora_alpha`（缩放，实际缩放=alpha/r）。
- 少数据（10条）→ 少步数 + 早停，防过拟合（背答案）。
- π0.5 默认**分位数归一化**，`stats.json` 必须有 `q01/q99`。

**你之前的训练**（从目录名反推）：`first100_fast_1000`=前100条+1000步；`100_200_fast_4000`=100~200条+4000步。数据少+步数少 = 真机成功率低，所以要自录重训。

### 3.6 评估子系统 —— 测量表现，产生反馈

| 项 | 内容 |
|---|---|
| 物理 | 本机跑 `eval_pi05_robot.py` + 你的人工判定 |
| 输入 | 每个 episode 的执行结果 |
| 输出 | 成功率（反馈给学习子系统） |
| 关键文件 | `eval_pi05_robot.py` |

**参数**：`--episodes`（次数，默认50）、`--steps-per-episode`（每集几个 50 帧 chunk）。

**流程**：复位 → 跑 → 你判定 y/n → 记录 → 打印累计成功率 → 写 `eval_results.log`。

**一个 chunk = 50 帧 ≈ 1.65s**。放试管要 5~15s，所以默认 1 个 chunk 太短，要 `--steps-per-episode 5`。

## 四、接口规格（系统论核心：成败在接口，不在零件）

系统论第三定律：**决定系统成败的是接口，不是部件**。你踩的每个坑，本质都是"接口不匹配"。这里把所有接口的**精确约定**列成清单——这就是系统的"合同"。

| # | 接口 | 精确约定 | 不匹配的后果 |
|---|---|---|---|
| I1 | 感知→决策（状态） | 7关节顺序 + **符号取负** + q01/q99 归一化 | 方向反了 / 数值乱飞 |
| I2 | 感知→决策（图像） | key=`base_0_rgb`+`left_wrist_0_rgb`；值∈[0,1]；内部 resize 224 | 报 image features missing |
| I3 | 感知→决策（语言） | `Task: {task}, State: {7整数};\nAction: `；max_length=200 | prompt 格式错 |
| I4 | 决策→执行（动作） | 动作不翻转，直接发；前7维有效 | 臂反向 / 维度错 |
| I5 | 执行→环境→感知 | 物理动作→世界改变→新状态/图（反馈） | —— |
| I6 | 示范→数据（录制） | 关节顺序、相机、single_task 文字固定 | 数据不可用 |
| I7 | 数据→学习（统计） | `stats.json` 的 q01/q99 一致 | 训练崩/损失异常 |
| I8 | 学习→决策（加载） | `PeftModel.from_pretrained(base, adapter)` | 加载失败 |
| I9 | 决策↔本机（网络） | SSH 隧道 `localhost:8080` | 连不上 |
| I10 | 物理层（CAN） | `can0` @ 1 Mbps | 电机无响应 |
| I11 | 物理层（串口） | `/dev/ttyUSB0` @ 1 Mbps，id 0~6 | 舵机 ping 不到 |
| I12 | 物理层（相机） | 640×480 + MJPG | fps 掉 / 读不到帧 |

**排障第一原则**：报错时先判断「是哪个接口断了/哪个约定不一致」，而不是「哪个零件坏了」。

## 五、两个反馈回路（系统的灵魂）

系统论第四定律：**反馈回路让系统从"死"到"活"**。你的系统有**两层嵌套闭环**：

### 5.1 内层 · 运行时闭环（秒级，推理部署时转）

```
感知(读状态+拍图) → 决策(模型推理50帧) → 执行(30fps发动作) → 环境改变 → 再感知 → …
```

这就是你问的"RTC / 推理一部分执行一部分"。当前实现是**分块闭环**：一次推理 50 帧 → 执行完 → 再推理。不是边推理边执行的流水线。

### 5.2 外层 · 学习闭环（天级，系统的真正主干）

```
示范(录数据) → 学习(微调) → 决策(部署) → 执行 → 评估(成功率)
      ↑__________________________________________________|
                       不达标 → 回到示范，再来一轮
```

**关键洞察：你之前所有工作，都是这个外层闭环上的一段弧线。**

| 你做的事 | 在闭环上的位置 |
|---|---|
| 遥操作录数据 | 示范节点 |
| 微调 / 换权重 | 学习节点 |
| 推理部署 / 评估脚本 | 决策+执行+评估节点 |

## 六、信息（数据）的完整生命周期

五种信息在系统里的完整旅程，一条线串起所有子系统：

```
1. 你手掰从臂（示范）—— 人的意图变成物理运动
2. 录制：从臂角度 + 主臂跟随 + 双相机图 + 指令 → 存成数据集
   （~/.cache/huggingface/lerobot/my_b601/place_tubes_<时间戳>/）
3. 微调：数据集 → lerobot-train → LoRA adapter（outputs/.../checkpoints/NNNN/）
4. 部署：adapter 被 predict_server.py 加载（BASE + ADAPTER 合体）
5. 推理：状态+图 → 隧道 → 模型 → 50×7 动作 → 隧道回本机
6. 执行：动作发 CAN → 主臂动 → 世界变
7. 评估：你判定成功/失败 → 成功率 → 决定是否回到第 1 步
```

## 七、系统当前状态诊断

| 层 | 状态 |
|---|---|
| 内层运行时闭环 | ✅ 已通（冒烟测试 4/4 + 真机跑通） |
| 外层学习闭环 | ❌ **断在起点**——示范节点（从臂）物理链路断路 |

**断点详情**：从臂 7 舵机全 ping 不到（`/dev/ttyUSB0` 能打开、电源灯亮、4 个波特率全 False）。这是**接口 I11 断路**（数据线没通，非软件/波特率问题），最可能是拓展坞 USB-串口问题。

**连带阻塞**：示范断了 → 录不了数据 → 学习/评估整条弧线无法启动。

**修复路径（让外层闭环转起来第一圈）：**

```
① 修 I11：从臂 USB 直插主板(不过拓展坞) → 重插总线 → 核对 ttyUSB0/ttyUSB1 → ping 通
② 修 I10 附带：夹爪校零（353.96°）—— lerobot-calibrate
③ 示范：录 10 条 place_tubes
④ 学习：lerobot-train（LoRA，~1500 步）
⑤ 部署：ADAPTER_DIR 指向新 checkpoint，重启服务器
⑥ 执行+评估：eval_pi05_robot.py 跑成功率
⑦ 反馈：不达标 → 回到 ③ 转第二圈
```
