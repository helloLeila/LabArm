# 评估子系统 · 技术详解

> 本文讲清楚「模型部署后怎么量化它到底行不行」——评估脚本 `eval_pi05_robot.py` 的技术实现 + 评估方法论。
> 定位：评估是整个学习闭环的**反馈节点**，它的输出（成功率）决定了"要不要再录数据重训"。

---

## 1. 评估在系统中的位置

```
示范(录数据) → 学习(微调) → 部署 → 执行 → 评估(成功率) ──不达标→ 回到示范
                                          ↑ 本文讲这个
```

评估回答一个唯一的问题：**"这个模型在我的真实场景里，成功完成任务的比例是多少？"** 这个数字直接决定闭环要不要继续转下一圈。

---

## 2. 为什么"成功"必须人工判定

放试管是**视觉-语义任务**，没有现成的自动判据（不像"电机转到某角度"能读编码器）。"试管是否准确放进橙色架的孔里"需要人看结果，所以评估脚本设计成：

- 每个 episode 跑完后，**提示你输入 `y`（成功）/ `n`（失败）**；
- 脚本只负责记录和算比例，不自己判断成败。

这是评估脚本最核心的设计约束：**机器负责执行，人负责判定。**

---

## 3. `eval_pi05_robot.py` 技术拆解

### 3.1 与 `run_pi05_robot.py` 的关系

评估脚本 = 单次执行脚本（`run_pi05_robot.py`）+ **三层外壳**：

| 层 | 技术实现 | 作用 |
|---|---|---|
| episode 循环 | `for ep in range(1, episodes+1)` | 重复跑 N 次 |
| 复位闸门 | `input("复位后按回车...")` | 每集前人工复位到相同初始状态 |
| 判定记录 | `input("成功? y/n/q")` + `results.append` | 人工判定 + 累计 |

底层的「读状态 → 拍照 → POST → 执行 50 帧」逻辑和单次脚本完全一样。

### 3.2 关键参数

```python
--episodes           # 评估次数（默认 50 = "50 次评估"）
--steps-per-episode  # 每集跑几个 50 帧 chunk（默认 1）
```

- `--episodes=50`：50 次采样，得到成功率。
- `--steps-per-episode`：控制每次评估的**时长上限**。一个 chunk = 50 帧 = 1.65s，放试管要 5~15s，所以默认 1 个 chunk 太短，要设 5~10。

### 3.3 每个 episode 的完整流程

```
1. input("复位场景+机械臂后按回车开始（q 退出）")
   └─ 人工把试管、架子、机械臂摆回标准初始状态（保证公平）
2. 跑 steps_per_episode 个 chunk：
      for step: 读状态 → 读双相机 → POST /predict → 执行 50 帧
3. input("成功? [y/n/q]")
   └─ 你判定，脚本记录
4. 打印累计成功率 + 追加写 eval_results.log
```

### 3.4 成功率计算与记录

```python
results.append(ans == 'y')
succ = sum(results)
print(f'当前成功率: {succ}/{len(results)} = {succ/len(results)*100:.1f}%')
with open(LOG, 'a') as f:
    f.write(f'episode {ep}: {"success" if ans == "y" else "fail"}\n')
```

- 成功率 = 成功数 / 已测数，**实时累计显示**，可随时 Ctrl+C 中断（已测的不丢）。
- `eval_results.log` 逐条追加，可事后追溯每次的成败。

### 3.5 安全设计（真机评估必需）

- **每集之间回车闸门**：保证你手不在工作区时才动。
- **全程 Ctrl+C 急停**：`except KeyboardInterrupt` 捕获，`finally` 里 `robot.disconnect()` 释放。
- 这两个设计是**真机评估的安全底线**，不能省。

## 4. 评估方法论（怎么让数字可信）

### 4.1 样本量：50 次够不够

成功率是**二项分布**的估计。50 次采样，成功率 60% 时，95% 置信区间约 ±13%（即真实值大概在 47%~73%）。所以：

- 50 次能给出**粗粒度**判断（"大概行/大概不行"）；
- 如果要区分 60% 和 70% 的差别，需要更多次（几百次）；
- 对你当前的阶段（判断"要不要重训"），50 次足够。

### 4.2 复位标准化（最容易忽略的公平性问题）

每个 episode 的初始状态（试管位置、机械臂位姿）**必须尽量一致**，否则成功率里混入了"起始条件差异"的噪声：

- 试管放回固定的起始位置；
- 机械臂回到 rest position（零位附近）；
- 干扰物摆回原位。

复位不标准 → 测出来的成功率不可比 → 反馈给学习的信号就是错的。

### 4.3 成功率 vs 训练的关系

| 现象 | 解读 | 行动 |
|---|---|---|
| 成功率 ≈ 0%，且动作乱 | 方向/接口错了，或完全没学会 | 查 STATE_FLIP、stats、重训 |
| 成功率低但动作"像" | 学会了大致动作，缺精细 | 多录数据、加步数 |
| 成功率突然变好/变坏 | 环境/复位/硬件变了 | 检查相机、校零、复位标准化 |

## 6. 评估的坑

| 坑 | 后果 | 应对 |
|---|---|---|
| `steps-per-episode=1`（默认太短） | 每次只动 1.65s，任务根本完不成，成功率全是 0 | 设 5~10 |
| 复位不标准 | 成功率不可比 | 固定试管/臂的初始位置 |
| 夹爪没校零 | `connect` 直接报 353.96° | 先 `lerobot-calibrate` |
| 相机编号漂了 | 图不对，动作乱 | 先 `v4l2-ctl --list-devices` |
| 成功率用太少样本 | 数字波动大 | 至少 20~50 次再下结论 |

---

## 7. 一句话总结

**评估 = 复用单次执行逻辑 + 三层外壳（episode 循环 / 人工复位闸门 / 人工判定），输出一个成功率数字，作为学习闭环的反馈信号。它最关键的三个技术点是：人工判定（视觉语义任务无自动判据）、复位标准化（保证公平）、样本量（50 次给粗粒度结论）。**
