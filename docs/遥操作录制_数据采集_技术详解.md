# 遥操作录制 & 数据采集 · 技术详解

> 本文从技术实现角度讲清楚「用手掰从臂示范 → 主臂跟随 → 录成可训练数据集」的完整过程。
> 覆盖：遥操作的双臂架构、从臂驱动的技术细节、`lerobot-record` 的录制循环、数据落盘结构、`stats.json` 的生成、相机配置与常见坑。
> 这份数据是整个学习闭环的**起点**——没有它，微调和部署都无从谈起。

## 1. 遥操作原理：双臂「示范-跟随」架构

遥操作（teleoperation）采集的本质是：**你用手掰从臂（leader）做正确动作，主臂（follower）实时跟随，同时把整个过程录下来当"标准答案"**。

```
     你的手
       ↓ 掰
┌─ 从臂 leader ─┐    读 leader 关节角     ┌─ 主臂 follower ─┐
│ FashionStar×7 │ ────────────────────→ │  达妙电机×7      │
│ /dev/ttyUSB0  │   (作为示范 action)    │  can0            │
└───────────────┘                        └──────────────────┘
       ↑ 记录 leader 角度 = action（"正确答案"）       ↑ 记录 follower 状态+相机图 = observation
```

**关键语义**（决定了训练数据怎么组织）：

- **action（动作）= leader 的关节角**：你手掰的位置，就是模型要学的"正确动作"。
- **observation（观测）= follower 的实际状态 + 相机图像**：模型在推理时能看到的"世界状态"。

训练时模型学的是：**「给定 follower 当前状态和相机图像，预测 leader 示范的动作」**。所以录数据时 action 和 observation 来自两个不同的臂，但它们的**关节顺序和语义是同一套**（7 个关节一一对应）。

## 2. 从臂（leader）驱动的技术细节

驱动文件 `rebot_arm_102_leader.py`，物理上是 FashionStar 总线舵机 ×7，串口 `/dev/ttyUSB0` @ 1 Mbps。

### 2.1 关节 id 映射

```python
joint_ids = {shoulder_pan: 0, shoulder_lift: 1, elbow_flex: 2,
             wrist_flex: 3, wrist_yaw: 4, wrist_roll: 5, gripper: 6}
```

7 个舵机在一条串口总线上**串联**，靠 id（0~6）区分。id 和关节名一一对应，顺序和主臂/模型完全一致。

### 2.2 `connect()` 做了什么（这就是你踩坑的地方）

```python
bus = FashionStarServo(port, baudrate=1_000_000)   # 打开串口
for motor_name, motor_id in joint_ids.items():
    if not bus.ping(motor_id):                       # 逐个 ping
        raise RuntimeError(f"Servo not found for {motor_name} (id={motor_id})")
    ...
```

**关键点**：`connect` 会对 7 个舵机**逐个 `ping`**，任何一个 ping 不通就立刻抛 `RuntimeError: Servo not found`。所以：

- 你看到的报错 `Servo not found for shoulder_pan (id=0)` 就是**第 0 号舵机没回应**。
- 7 个全 ping 不到 = 串口数据线物理没通（总线串联，上游断一个全失联），**不是软件/波特率问题**。

### 2.3 `calibrate()`（从臂校零）

```python
# 提示手动摆零位 + 夹爪闭合，回车
for motor_name, motor_id in joint_ids.items():
    bus.unlock(motor_id)              # 解锁（舵机默认可能锁转）
    bus.set_origin_point(motor_id)    # 把当前位置定为 0°
    self.calibration[motor_name] = MotorCalibration(..., range_min=-90, range_max=90)
```

技术要点：FashionStar 舵机是**相对角度**，`set_origin_point` 把当前物理位置写为 0°。校准范围默认 ±90°。

```python

```

## 3. `lerobot-record` 录制命令逐参数

```bash
lerobot-record \
  --robot.type=seeed_b601_dm_follower \
  --robot.port=can0 \
  --robot.cameras="{front: {type: opencv, index_or_path: 6, width: 640, height: 480, fps: 30, fourcc: MJPG}, wrist: {type: opencv, index_or_path: 4, width: 640, height: 480, fps: 30, fourcc: MJPG}}" \
  --teleop.type=rebot_arm_102_leader \
  --teleop.port=/dev/ttyUSB0 \
  --dataset.repo_id=my_b601/place_tubes \
  --dataset.num_episodes=10 \
  --dataset.single_task="place two test tubes into the orange rack" \
  --dataset.push_to_hub=false
```

| 参数 | 技术含义 |
|---|---|
| `--robot.type=seeed_b601_dm_follower` | 主臂用自定义驱动（走 CAN） |
| `--robot.port=can0` | CAN 接口名（不是 `damiao/ttyACM0`） |
| `--robot.cameras=...` | 双相机：front=video6、wrist=video4，都 640×480 + MJPG + 30fps |
| `--teleop.type=rebot_arm_102_leader` | 从臂驱动名（**不是**内置 `rebot_102_leader`，那个 joint_directions 不对） |
| `--teleop.port=/dev/ttyUSB0` | 从臂串口 |
| `--dataset.repo_id=my_b601/place_tubes` | 数据集仓库名（本地缓存键） |
| `--dataset.num_episodes=10` | 录几段 |
| `--dataset.single_task=...` | **每帧都会写进数据里的任务文字**，训练/推理要一字不差 |
| `--dataset.push_to_hub=false` | 只存本地，不传 HuggingFace |

**两个容易忽略的技术约束**：

1. **不要加 `--robot.id`**：lerobot 用 `id` 决定校准文件名（`calibration_dir/{id}.json`）。默认 `id=None` → 校准文件是 `None.json`。加了别的 id 就找不到之前的校准，`connect` 会强制重新校零。

2. **`dataset.fps` 必须和相机 fps 一致**：录制循环里有 `if dataset.fps != fps: raise ValueError`。所以相机设 30fps、数据集也按 30fps 录。

## 4. 录制循环的技术细节（`record()` 函数）

lerobot 的录制核心是一个**按固定帧率的循环**：

```python
timer = CycleTimer(fps, records_data=dataset is not None)   # 帧率节拍器
...
while recorded_episodes < num_episodes and not stop_recording:
    # 每个 episode 内：
    #   1. reset 阶段：回到 rest position（起始位姿）
    #   2. 循环：读 leader → 驱动 follower → 记录一帧
    frame = {**observation_frame, **action_frame, "task": single_task}
```

### 4.1 一帧数据里有什么

每帧 `frame` 由三部分组成：

```python
{
    # observation（观测）—— 推理时能看到的
    "observation.state": [7 关节角],           # follower 的实际状态
    "observation.images.front": <图像>,          # 俯瞰相机
    "observation.images.wrist": <图像>,          # 腕部相机
    # action（动作）—— 模型要学的"正确答案"
    "action": [7 关节角],                        # leader 的示范角度
    # 任务标签
    "task": "place two test tubes into the orange rack",
}
```

**这就是为什么"动作和观测来自不同臂"不影响训练**——它们只是同一帧里两个字段，训练时模型拿 observation 预测 action，比对的就是你示范的 leader 角度。

### 4.2 `CycleTimer` 帧率节拍器

`CycleTimer(fps)` 保证循环**严格按 30fps 采帧**：如果一帧的处理耗时超过 1/30s，它会跳过或补偿，保证帧间时间戳均匀。这很重要——模型的"动作块"隐含了时间信息，采帧不均匀会让模型学到错误的时序。

### 4.3 episode 的 reset 阶段

每个 episode 开始前有一个**复位阶段**：把机械臂回到起始位姿（rest position）。这样每条 episode 都从相同的初始状态开始，训练数据更干净。对应录制按键的**第二次 `n`**：第一次结束动作，第二次结束复位。

### 4.4 兼容性检查

```python
sanity_check_dataset_robot_compatibility(dataset, robot, fps, dataset_features)
```

录制前会检查：相机数量/名称、关节数量/名称、fps 是否和已有数据一致。**如果中途换相机或改关节，这里会报错**，防止录出"混搭"的数据集。

## 5. 数据落盘结构与 `stats.json` 生成

### 5.1 物理结构

```
~/.cache/huggingface/lerobot/my_b601/place_tubes_<时间戳>/
├── videos/
│   ├── observation.images.front/      # 俯瞰视频（按 episode 分片）
│   └── observation.images.wrist/      # 腕部视频
├── data/
│   └── chunk-000/xxx.parquet          # 每帧状态+动作（表格，分块存）
└── meta/
    ├── stats.json                     # 归一化统计（训练必读）
    └── info.json                      # 元信息（关节名、指令、fps、episode 数）
```

### 5.2 `stats.json` 里有什么、怎么生成

```json
{
  "observation.state": {"q01": [...7个...], "q99": [...7个...]},
  "action":            {"q01": [...7个...], "q99": [...7个...]},
  "observation.images.front": {"mean": ..., "std": ...},
  ...
}
```

技术要点：

- **π0.5 用分位数归一化**，读 `q01`（第 1% 分位）和 `q99`（第 99% 分位），不是 min/max/mean/std。
- 录制时 lerobot 会**聚合每个 episode 的分位数摘要**，存进 `stats.json`。
- ⚠️ **风险点**：录制生成的是"保守包络"（`q≤50 取 min`、`q>50 取 max`），数据量少（10 条）时这个统计可能不够准。可以训练后用 `augment_dataset_quantile_stats.py` 扫描全数据集的真实分位数重算。

### 5.3 训练和推理都读同一份 `stats.json`

这正是部署文档里 `STATS_PATH` 的由来——**训练用这份统计归一化，推理也必须用同一份**，否则数值对不上。

## 6. 相机配置（录制特有的坑）

录制走 `lerobot-record`，相机配置和推理脚本有**一处关键不同**：

| 项 | 录制命令 | 推理脚本 | 原因 |
|---|---|---|---|
| front 分辨率 | **640×480** | 848×480 | 录制有 `_validate_fps` 校验，848×480 只有 15fps 会报错；推理脚本直接 `cv2.read()` 不校验 |

其余一致：都必须 **`fourcc: MJPG`**（否则 `select()` 超时读不到帧）、30fps。

---

## 7. 录制按键状态机

| 键 | 动作 | 技术含义 |
|---|---|---|
| `n` / → | 保存当前 episode，进入下一个 | 第一次 `n` 结束动作、第二次 `n` 结束复位 |
| `r` / ← | 丢弃当前 episode 重录 | 不写入磁盘 |
| `q` / Esc | 退出录制 | 已完成的部分保留 |

**录制节奏**：每段按两次 `n`（动作 + 复位），录满 `num_episodes` 段自动结束。

## 8. 录制前 checklist（一次全过，少返工）

按依赖顺序排：

1. **从臂 ping 通**：`python ping_leader.py` 7 个全 True（否则 `Servo not found`）。
2. **串口权限**：`usermod -aG dialout $USER`（否则 `Permission denied`）。
3. **主臂夹爪校零**：`lerobot-calibrate`（否则 connect 报 353.96°）。
4. **相机编号**：`v4l2-ctl --list-devices` 确认 front=video6、wrist=video4。
5. **相机参数**：640×480 + MJPG（否则 fps/超时报错）。

## 9. 常见坑速查

| 症状 | 技术根因 | 修复 |
|---|---|---|
| `Servo not found (id=0)` | 从臂数据线没通（总线串联，上游断全断） | USB 直插主板、重插总线、核对 ttyUSB0/ttyUSB1 |
| `Permission denied` | 不在 dialout 组 | `usermod -aG dialout $USER` |
| `failed to set fps=30 (actual_fps=15)` | 848×480 只支持 15fps | 改 640×480 |
| `Timed out waiting for frame` | fourcc 探测错 | 加 `fourcc: MJPG` |
| `gripper not homed, offset 353.96°` | 夹爪零点漂 | `lerobot-calibrate` 重校零 |
| 数据不兼容报错 | 换相机/改关节/fps 不一致 | 保持录制参数全程一致 |

---

## 10. 一句话总结

**遥操作录制 = 你掰从臂（leader 角度 = 动作"标准答案"）+ 主臂跟随（follower 状态+相机 = 观测）+ `lerobot-record` 按 30fps 逐帧记录，落盘成 videos/data/meta 三件套，其中 `stats.json` 的 q01/q99 分位数是后续训练和推理共用的数值契约。当前阻塞点就是从臂串口数据线没通，导致示范这一环无法启动。**
